# 轮廓内矩形物体摆放求解器

**这个程序干什么**:给它一个房间的平面图、门在哪儿、以及一堆货架冰箱的尺寸,
它告诉你每件东西该放在哪、朝哪个方向,保证不叠在一起、不穿墙、不堵门,
并且尽量都靠墙放。

---

## 1. 核心代码实现逻辑说明

### 1.1 AI 工具使用说明

**使用的 AI 工具**:Claude(Claude Code CLI)。

**AI 主要帮助的部分**:


- **代码生成**:几何清洗、候选生成、搜索、可视化、测试各模块的初版代码。
- **Debug**:帮我定位了冰箱开门区假设定得太严、导致两个样例误判为无解的问题
  (详见 1.6)。
- **技术选型**:排除了 OR-Tools CP-SAT。它的 `add_no_overlap_2d` 只能处理
  正南正北的矩形,而 example1 的房间有两面斜墙,家具得跟着斜墙歪着放。硬要用
  它,要么把家具的包围盒放大(解变差),要么按方向分组求解多次(复杂度反而
  超过自己写搜索)。
- **容差怎么定**:发现输入里有一面墙的方向是 179.975 度,比 180 度歪了
  0.025 度,肉眼根本看不出来。据此定下"贴墙用精确角度、归类用容差角度"的
  双轨做法(见 1.2)。

**我自己理解并调整的关键逻辑**:
- **思路拆解**:帮我确认了"这题不是通用的二维装箱问题"。因为题目要求"优先
  贴墙",可以把"在平面上任意位置找坐标"简化成"沿着墙排队",难度差一个量级,
  也就不需要上模拟退火之类的元启发式算法了。
- **冰箱开门约束拆成三条**:我把"开门区不能有东西"(题目硬要求)、"开门区不能
  穿墙"(物理前提)、"开门区可以和入户门的活动范围重叠"(现实可接受)分成了三条
  独立的约束。初版把这三件事混成一条,直接导致两个样例算出"放不下"。
- **将冰箱的开门半径设置为600mm**:"冰箱门前不能放东西“这句话太过于模糊，如果冰箱门对面是贴墙放置的货物架，冰箱是否可以打开？按照开门的规则
我将冰箱门半径设为600mm.


### 1.2 第一步:先把图纸洗干净(`layout/geometry.py的作用`)

输入的轮廓是从 CAD 导出来的,带着制图的"毛刺"。不先清理,后面的计算根本跑
不起来。一共三类问题:

| 问题 | 实例 | 怎么处理 |
|---|---|---|
| 首尾闭合方式不统一 | example1/2/3 的最后一个点重复了第一个点,example4 没有 | 统一去掉重复的尾点 |
| 轮廓自己贴到自己 | example4 的最后一个点绕回到了第 2 个点,shapely 直接报 `Ring Self-intersection` | 用 `make_valid()` + `buffer(0)` 修好,取面积最大的那块 |
| 制图留下的细缝 | example2 有个 30×100mm 的小凹槽(门套或墙厚的痕迹) | 过滤掉长度小于 200mm 的边,这种边比最窄的家具还窄,贴上去也放不下东西 |
| 顶点绕向不固定 | 各样例顺时针逆时针都有 | 统一成逆时针,另外用"探针"再确认一次哪边是室内 |

洗完之后对比面积,确认只去掉了零面积的毛刺、没动真实空间:

| 样例 | 原始数据能否直接用 | 清洗后面积 | 顶点数变化 | 可贴的墙 |
|---|---|---|---|---|
| example1 | 可以 | 8.8131 m² | 6 → 6 | 6 条 |
| example2 | 可以 | 7.7039 m² | 14 → 10 | 6 条 |
| example3 | 可以 | 11.5190 m² | 8 → 8 | 8 条 |
| example4 | **不可以** | 6.5730 m² | 11 → 10 | 9 条 |

有个细节可以佐证清洗是对的:example1 算出来 8.8131 m²,而
`reference/image01.png` 上标注"储物区面积 8.8m²"。两者吻合,说明参考图就是
对应这个样例的,可以直接拿来对比程序输出。

**关于那 0.025 度的歪斜**:example1 有一面墙方向是 179.975 度,长 1325mm。
这一个细节牵出两条规则:

- 相邻两条边方向差小于 0.5 度才合并。不然同一面墙会被切成两段,生成两个几乎
  一样、只差 0.03 度的候选方向,白白增加搜索量。
- 贴墙时用每面墙**自己的精确角度**,不做归一化。如果把 179.975 度当成 180 度,
  沿着 1325mm 长的墙走下来会累积约 0.6mm 的偏差,家具就戳出墙外了。归一化后的
  角度只用来生成"离墙摆放"的候选方向。

### 1.3 第二步:列出所有值得一试的位置(`layout/candidates.py的作用`)

**朝向怎么定**。题目说家具要跟轮廓边平行或垂直。example1 的斜墙说明这不能
理解成"跟 x/y 轴平行",必须是**跟它自己贴的那面墙**平行。所以我给每面墙建了
一套局部坐标(u 沿着墙走,v 指向室内),家具的朝向用相对角 φ 表示:

| φ | 沿墙方向的长度 | 占的进深 | 冰箱开门边朝哪 |
|---|---|---|---|
| 0 | length | width | 朝室内 |
| 90 | width | length | 沿墙反向 |
| 180 | length | width | 朝墙(冰箱不能用) |
| 270 | width | length | 沿墙正向 |

普通矩形转 180 度跟没转一样,所以只需要试 φ = 0 和 90 两种。冰箱得区分开门边
朝哪边,要试 φ = 0、90、270 三种,其中 180 排除掉(开门边顶着墙,门打不开)。

**位置怎么定**。这是整个方案的关键。墙上的位置是连续的,不可能一毫米一毫米
地试。但你想想自己摆家具的动作:你只会把它**推到墙角**,或者**推过去贴紧
旁边已经摆好的那件**,不会故意在中间留 37 毫米的缝。

所以候选位置只取这三类"接触点":

1. 墙段的两端(贴到墙角)
2. 已摆好的家具在这面墙上的投影端点(推过去贴紧它)
3. 轮廓顶点的投影(L 形房间里在拐角处停住)

这样做为什么不会漏掉最优解:任何合法的贴墙摆放,都可以沿墙继续往前推,直到
顶住某个边界而仍然合法。所以最优解一定是跟某个已有边界对齐的,接触点枚举
刚好覆盖了所有这种位置。好处是候选数量只跟"已摆了几件"有关,而不是跟"墙有
多长、步长多细"有关。

还有个判断:哪些已摆好的家具会真的挡住这次摆放?只算那些**进深范围有重叠**
的。贴在对面墙上的家具虽然投影到同一条墙轴上,但根本挡不住这边,不该算进来。

### 1.4 第三步:检查三条禁令(`layout/constraints.py的作用`)

- **门**:先用"探针"判断门往哪边是室内(不依赖轮廓绕向,更稳)。外开门留
  50mm 的通行带;内开门按题目要求留 N×N 的正方形(N 是门宽),也就是门扇
  扫过那个扇形的包围盒。
- **冰箱**:开门边(也就是 length 所在那条边)前方留出 `length × 600mm`,
  这块地方不许有任何东西。
- **怎么判断"没戳出墙外"**:不能简单地把可用区域放大一点来容忍误差,因为那
  会连门禁区一起放宽。改成看"溢出面积":允许沿着家具周长平均 0.5mm 的浮点
  噪声,但 1220×50 这种真实越界照样会被拒。

### 1.5 第四步:搜索(`layout/solver.py的作用`)

**先放难放的**:冰箱 → 制冰机 → 货架 → 离地架。冰箱又大、又带开门约束,
要是留到最后放,很容易发现没地方了。

**好坏怎么比**,按优先级从高到低:放下的件数 → 贴墙的件数 → 总的离墙距离
(越小越好)。

**"优先贴墙"按硬要求实现**,分两轮:

1. **第一轮只允许贴墙**;
2. 只有第一轮放不下全部物体,第二轮才允许剩下的离墙放(但仍然要跟某面墙平行)。

每一层把候选按"紧凑度"排序,只试前 14 个。紧凑度就是看这个位置沿墙方向有
几侧被顶住(0、1 或 2 侧),两侧都顶住说明刚好填满一个空隙,优先试。走到死路
就退回上一步换个位置,也就是回溯。

四个样例实际只搜了 57-138 个节点,离 40 万的上限差得很远。

### 1.6 一处关键的假设修正

初版我把冰箱开门区定成"门板全开扫过的 1220×1220 包围盒",还要求这块区域完整
落在扣掉门禁区之后的可用空间里。结果 example3 和 example4 的冰箱**一个能放的
位置都没有**。

怎么查出原因的:对可用区域做负向 buffer,测房间最宽的通道有多宽。example3 的
`buffer(-750)` 结果是空的,说明整个房间最宽处只有 1400-1500mm。而冰箱当时需要
1330(自身进深)+ 1220(开门区)= 2550mm,横竖都放不进去。

这不是真的放不下,是我的假设太严。题目只写了"开门边不能放任何东西",并没要求
预留门板全开的那一整块。所以改了两点:

- 预留进深从 1220mm 改成 **600mm**。600 是取东西需要的最小身位,也是厨房设计
  里电器前面常用的通行净宽;
- 把"开门区不能穿墙"和"开门区不能碰入户门的活动范围"拆开。墙是实的,穿不过去;
  但两扇门共用活动空间,只意味着不能同时打开,这在现实中太常见了,默认允许
  (`Config.fridge_clearance_vs_door_zone = False`)。

改完四个样例全部可行。这个假设的影响是实测出来的,不是我猜的:

| 开门区进深 | example3 冰箱能放的位置数 | example4 |
|---|---|---|
| 1220mm(门板全开) | **0** | **0** |
| 600mm(当前默认) | 2 | 6 |
| 300mm | 4 | 12 |

example3 最后的方案里,冰箱开门区和入户门活动范围重叠了 0.336 m²。这是这个
设定下的必然结果,不是搜索没找到:实测在 600mm 进深下,能完全避开门活动范围
的冰箱位置数是 **0**。如果一定要严格禁止重叠,把
`Config.fridge_clearance_vs_door_zone` 改成 True、同时把进深降到 300mm 即可。

## 2. 运行环境及运行方式

### 环境

- Python 3.9 以上(我用 3.10.11 开发和验证)
- 依赖四个包:`shapely` 2.1.2、`matplotlib` 3.10.9、`numpy` 2.2.6、
  `pytest` 8.3.4

`shapely` 是核心依赖,负责修复破损的多边形和做区域的加减运算,前面说的那些
脏数据全靠它处理。没用 OR-Tools 之类的求解器,原因见 1.1。

### 安装

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

### 运行

```bash
# 跑一个样例
python main.py examples/example1.json

# 跑一个样例,同时出图(图存到 output/)
python main.py examples/example1.json --plot

# 一次跑完四个样例并出图
python main.py --all --plot

# 把结果存成 JSON
python main.py examples/example1.json -o output/example1_result.json

# 调整冰箱开门区进深(默认 600mm)
python main.py examples/example3.json --fridge-clearance 300
```

全部可行时退出码是 0,有样例放不下则返回 1。

**在 PyCharm 里点运行按钮**需要先配参数,否则会提示"需指定输入文件":
右上角配置下拉 → `Edit Configurations` → Script path 选 `main.py`,
Parameters 填 `--all --plot`,Working directory 确认是项目根目录。
最后这条别漏,代码里用的是 `examples/*.json` 这样的相对路径。

**Windows 终端中文可能显示成乱码**,因为 cmd 和 Git Bash 默认是 GBK 编码。
数字和坐标不受影响。想正常显示先执行 `chcp 65001`,或者直接用 PyCharm 自带的
运行窗口(UTF-8)。

### 测试

```bash
python -m pytest tests/ -q
```

当前 61 passed、3 skipped(跳过的是"外开门样例不检查内开门规则"、"没冰箱的
样例不检查冰箱规则"这类条件性断言)。测试分两部分:

- `tests/test_geometry.py`:图纸清洗的回归测试。包括确认 example4 的原始数据
  确实无效、清洗不改变面积、面积回归值、30mm 凹槽确实被排除、0.025 度的斜边
  确实被保留、顺时针输入也能算对内法向等。
- `tests/test_constraints.py`:对输出结果做全约束校验。包括没戳出墙外、两两
  不重叠、没堵门、内开门确实留了 N×N、冰箱开门区没东西且没穿墙、角度确实跟
  某面墙平行或垂直、标记为贴墙的确实贴着墙、尺寸没被意外缩放等。

出图只能看出明显的错误,毫米级的越界和零宽度的重叠必须靠数值断言兜住,所以
这些测试是判断对错的主要依据。

### 输入格式

```json
{
  "boundary": [[x1, y1], [x2, y2], "..."],
  "door": [[x1, y1], [x2, y2]],
  "isOpenInward": false,
  "algoToPlace": { "fridge": [1220, 1330], "shelf-1": [1000, 400] }
}
```

单位是毫米。`boundary` 首尾闭不闭合都能处理。物体名字里的 `-数字` 后缀会被
去掉用来识别类型(`fridge` / `shelf` / `overShelf` / `iceMaker`)。

### 输出格式

```json
{
  "feasible": true,
  "placements": {
    "fridge": {
      "center": [5191.8913, 31931.0171],
      "angle": 195.852,
      "size": [1220.0, 1330.0],
      "againstWall": true
    }
  },
  "unplaced": [],
  "stats": { "nodes": 138, "note": "全部贴墙" }
}
```

**角度怎么读**:逆时针为正,单位是度,范围 `[0, 360)`。`angle = 0` 表示物体的
length 沿着 +x 方向、width 沿着 +y 方向,也就是题目给定尺寸的初始状态。
冰箱的开门边固定在局部 +y 那一侧,所以冰箱的角度需要在 0-360 度里区分朝向;
普通矩形转 180 度跟没转一样,不用区分。

## 4. 已知局限

- **贴墙这个目标达到了,但空间用得不够均匀**。四个样例都做到了 100% 贴墙,
  满足题目要求,但家具倾向于挤在排序靠前的长墙上(比如 example3 九件里有七件
  都沿着左墙),房间中间空着一大片。如果希望布局更均衡,可以在好坏判断里加一项
  "墙面使用的分散度"。
- **离地架按不能重叠处理**。`reference/image01.png` 上标注离地架高 120mm,
  物理上底下其实能塞东西。但这题是二维的,当前实现不允许任何重叠。如果允许,
  能放下的概率会明显提高。
- **冰箱开门区的 600mm 是我定的假设**,题目没给这个数。可以用
  `--fridge-clearance` 调,影响见 1.6 的实测表格。
- **没有检查"路走不走得通"**。目前只保证门口不被堵,但不检查从门到每件家具
  之间是否真的有路可走。在更窄的房间里,理论上可能出现家具围成死角的布局。
- **接触点枚举会留下小缝隙**。先放的家具会把自己的开门区边界固定下来,后放的
  家具从另一头往里排时,未必刚好能对齐。比如 example4 里 overShelf-1 的顶边
  和冰箱开门区之间空了 30mm。这只是没利用上的空间,不违反任何约束。
