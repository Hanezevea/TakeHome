# 轮廓内矩形物体摆放求解器

给定房间轮廓、门的位置与类型、若干矩形物体尺寸，求一组不重叠、不越界、
不遮挡门、且尽可能贴墙的摆放方案，输出每件物体的中心点坐标与旋转角度。

四个既定样例全部可行，9 件以内物体的求解时间在 0.1 秒量级。

---

## 1. 核心代码实现逻辑说明

### 1.1 AI 工具使用说明

**使用的 AI 工具**：Claude（Claude Code CLI）。

**AI 主要帮助的部分**：

- **思路拆解**：确认了"这不是通用 2D 装箱问题"这一判断。因为题目明确
  "优先贴墙"，可以把二维平面上的连续位置搜索降为沿墙的一维排布问题，
  从而避免引入元启发式算法。
- **代码生成**：几何清洗、候选生成、DFS 搜索、可视化、测试各模块的初版代码。
- **Debug**：定位了冰箱开门区假设过严导致 example3/4 无解的问题（详见 1.6）。

**我自己理解并调整的关键逻辑**：

- **技术选型**：排除了 OR-Tools CP-SAT。其 `add_no_overlap_2d` 只支持轴对齐
  矩形，而 example1 存在相差约 15.85 度的两套墙面方向，建模时要么放大包围盒
  导致解质量下降，要么按方向分组多次求解导致复杂度反超手写搜索。
- **候选位置的离散化方式**：不用均匀网格，改用接触点枚举（见 1.3）。这是
  整个方案可行性的关键，直接决定了搜索规模是 O(已放置数) 还是 O(墙长/步长)。
- **冰箱开门约束的三层拆解**：把"开门区不被物体占用"（题目硬要求）、
  "开门区不越出墙体"（物理前提）、"开门区可与入户门扇区重叠"（现实可接受）
  区分为三条独立约束。最初实现把三者混为一条，导致两个样例误判为无解。
- **容差策略**：发现输入中存在 179.975 度的墙面（偏离 180 度仅 0.025 度），
  据此确定了"贴墙用精确角度、聚类用容差角度"的双轨处理（见 1.2）。

### 1.2 第一步：轮廓清洗（`layout/geometry.py`）

输入的 `boundary` 直接来自 CAD 导出，存在三类脏数据，不处理无法进入后续计算：

| 问题 | 实例 | 处理 |
|---|---|---|
| 闭合方式不一致 | example1/2/3 首尾点重复，example4 不重复 | 统一去掉与首点重合的尾点 |
| 退化自接触环 | example4 末点回绕到第 2 个点，shapely 报 `Ring Self-intersection` | `make_valid()` + `buffer(0)`，取最大面积分量 |
| 制图伪影 | example2 存在 30×100mm 凹槽（门套/墙厚残留） | 过滤长度 < 200mm 的边，不作为可贴墙面 |
| 绕向不固定 | 各样例不一致 | 规范为逆时针，内法向另用探针校验 |

清洗后对四个样例做面积回归，确认只去除了零面积退化结构：

| 样例 | 原始构造是否有效 | 清洗后面积 | 顶点数变化 | 有效墙边 |
|---|---|---|---|---|
| example1 | 有效 | 8.8131 m² | 6 → 6 | 6 |
| example2 | 有效 | 7.7039 m² | 14 → 10 | 6 |
| example3 | 有效 | 11.5190 m² | 8 → 8 | 8 |
| example4 | **无效** | 6.5730 m² | 11 → 10 | 9 |

example1 算得 8.8131 m²，与 `reference/image01.png` 标注的"储物区面积 8.8m²"
一致，据此确认参考图与样例的对应关系，可直接用于校验输出。

**关于 0.025 度的微小倾斜**：example1 的一条边方向角为 179.975 度，长 1325mm。
这导致两条处理规则：

- 相邻边方向差小于 0.5 度才合并，否则同一面墙会被切成两段，生成两个几乎
  相同、只差 0.03 度的候选朝向；
- 贴墙摆放使用各边的**精确角度**，不做归一。若把 179.975 度归到 180 度，
  沿 1325mm 的墙会累积约 0.6mm 偏差而戳出轮廓。方向聚类的容差角度只用于
  生成离墙摆放的候选朝向。

### 1.3 第二步：候选生成（`layout/candidates.py`）

**朝向**：题目要求物体与轮廓边平行或垂直。example1 的斜墙说明这不能理解为
全局轴对齐——必须相对于**物体所贴的那面墙**。因此每面墙建立局部坐标系
（u 沿墙、v 指向室内），朝向用相对角 φ 表达：

| φ | 沿墙跨度 | 进深 | 开门边朝向 |
|---|---|---|---|
| 0 | length | width | 室内 |
| 90 | width | length | 沿墙反向 |
| 180 | length | width | 朝墙（冰箱不可用） |
| 270 | width | length | 沿墙正向 |

普通矩形 180 度对称，只需 φ ∈ {0, 90}；冰箱需区分开门边指向，用
φ ∈ {0, 90, 270}，排除 180（开门边朝墙）。

**位置**：这是方案可行性的关键。沿墙位置是连续的，不做均匀网格采样，只取
**接触点**：

1. 墙段两端（贴角）
2. 已放置物体在该墙轴上的投影端点（推紧贴靠）
3. 轮廓顶点的投影（L 形房间里在凹角处停住）

依据是：任何合法的贴墙解都可以沿墙继续推紧直到顶住某个边界而仍然合法，
因此最优解必然与某个已有边界对齐，接触点枚举不会漏解。候选数因此是
O(已放置数) 而非 O(墙长/步长)。

判断"哪些已放置物体会沿某面墙构成阻挡"时，只计入进深区间与待放物体
[0, depth] 相交的物体。贴在对面墙上的物体虽然投影到同一墙轴，但不会挡住
本次摆放。

### 1.4 第三步：约束校验（`layout/constraints.py`）

- **门**：门段向室内的法向用探针判定（不依赖绕向）。外开门预留 50mm 通行带；
  内开门按题目要求预留 N×N（N = 门宽），即门扇扫过扇形的包围盒。
- **冰箱**：开门边（length 所在边）前方预留 `length × 600mm`，该范围内不得
  有任何物体。
- **包含性判断**：不对自由区域做 buffer 膨胀（那会同时放宽墙体与门禁区），
  改为按"溢出面积"判定——允许沿周长平均 0.5mm 的浮点噪声，但 1220×50 这种
  真实越界仍会被拒。

### 1.5 第四步：搜索（`layout/solver.py`）

摆放顺序按难度降序：冰箱 → 制冰机 → 货架 → 离地架。冰箱带开门约束且面积
最大，若最后放极易无解。

目标函数按字典序：**放置件数 > 贴墙件数 > 总离墙距离（越小越好）**。

"优先贴墙"按硬优先实现，分两阶段：

1. 只用贴墙候选做 DFS；
2. 仅当阶段一无法全部放下时，才允许剩余物体离墙摆放（仍与某面墙平行）。

每层按紧凑度（沿墙方向被顶住的侧数 0/1/2）排序后取前 14 个分支。两侧都
顶住意味着恰好填满一个空隙，优先探索。四个样例的实际搜索节点数为 57-138，
远未触及 400000 的上限。

### 1.6 一处关键的假设修正

初版把冰箱开门区的预留进深取为 `length`（1220mm），即门板全开扫过的
1220×1220 包围盒，并要求该区域完整落在扣除门禁区后的自由区域内。结果
example3 与 example4 的冰箱**没有任何合法位置**。

诊断过程：对自由区域做负向 buffer 测试最大内接通道宽度，example3 的
`buffer(-750)` 为空，说明房间最宽通道仅 1400-1500mm；而冰箱当时需要
1330（进深）+ 1220（开门区）= 2550mm，任何朝向都放不下。

这不是真正不可行，是假设过严。题目只写"开门边不能放任何东西"，并未要求
预留门板全开的包围盒。修正为两点：

- 预留进深取 **600mm**（取物所需最小身位，也是厨房设计中电器前的常用通行
  净宽），而非 1220mm；
- 把"开门区不得越出墙体"与"开门区不得与入户门扇区重叠"拆开。墙体不可穿越
  是物理约束；两扇门共用摆动空间只意味着不能同时打开，现实中普遍可接受，
  默认允许（`Config.fridge_clearance_vs_door_zone = False`）。

修正后四个样例全部可行。该假设的影响是实测的，不是推测的：

| 开门区进深 | example3 冰箱合法贴墙位置数 | example4 |
|---|---|---|
| 1220mm（门板全开） | **0** | **0** |
| 600mm（当前默认） | 2 | 6 |
| 300mm | 4 | 12 |

example3 的最终方案中，冰箱开门区与入户门扇区重叠 0.336 m²。这是该设定下的
必然结果：实测在 600mm 进深下，完全避开门扇区的冰箱合法位置数为 **0**。
若需严格禁止重叠，把 `Config.fridge_clearance_vs_door_zone` 置 True 并把
进深降到 300mm。

## 2. 运行环境及运行方式

### 环境

- Python 3.9+（开发与验证使用 3.10.11）
- 依赖：`shapely` 2.1.2、`matplotlib` 3.10.9、`numpy` 2.2.6、`pytest` 8.3.4

`shapely` 承担多边形修复与布尔运算，是处理上述脏数据的核心依赖。
未使用 OR-Tools 等求解器，原因见 1.1。

### 安装

```bash
python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

### 运行

```bash
# 求解单个样例
python main.py examples/example1.json

# 求解并输出可视化 PNG 到 output/
python main.py examples/example1.json --plot

# 批量求解全部样例
python main.py --all --plot

# 结果写入 JSON
python main.py examples/example1.json -o output/example1_result.json

# 调整冰箱开门区进深（默认 600mm）
python main.py examples/example3.json --fridge-clearance 300
```

退出码：全部可行返回 0，存在不可行样例返回 1。

### 测试

```bash
python -m pytest tests/ -q
```

当前 61 passed, 3 skipped（跳过项为外开门样例的内开门断言、无冰箱样例的
冰箱断言）。测试覆盖两部分：

- `tests/test_geometry.py`：轮廓清洗的回归测试，包括 example4 原始数据
  确实无效、清洗不改变面积、面积回归值、30mm 凹槽被排除、0.025 度倾斜边
  被保留、内法向在顺时针输入下仍正确等。
- `tests/test_constraints.py`：对输出做全约束校验，包括不越界、两两不重叠、
  不遮挡门、内开门预留 N×N、冰箱开门区无物体且不越墙、角度与某面墙平行或
  垂直、标记贴墙的物体确实贴墙、尺寸未被缩放等。

出图只能发现明显错误，毫米级越界与零宽度重叠必须靠数值断言兜住，因此这些
测试是正确性的主要依据。

### 输入格式

```json
{
  "boundary": [[x1, y1], [x2, y2], "..."],
  "door": [[x1, y1], [x2, y2]],
  "isOpenInward": false,
  "algoToPlace": { "fridge": [1220, 1330], "shelf-1": [1000, 400] }
}
```

单位为毫米。`boundary` 首尾闭合与否均可。物体名称的 `-数字` 后缀会被去掉
以识别类型（`fridge` / `shelf` / `overShelf` / `iceMaker`）。

### 输出格式

```json
{
  "feasible": true,
  "placements": {
    "fridge": {
      "center": [5191.8913, 31931.0171],
      "angle": 195.852,
      "size": [1220.0, 1330.0],
      "againstWall": true
    }
  },
  "unplaced": [],
  "stats": { "nodes": 138, "note": "全部贴墙" }
}
```

**角度约定**：逆时针为正，单位度，取值 `[0, 360)`。`angle = 0` 时物体
length 沿 +x、width 沿 +y，即给定尺寸的初始角度。冰箱的开门边固定为局部
+y 一侧，因此冰箱角度需在 0-360 内区分；普通矩形 180 度对称。

## 4. 已知局限

- **贴墙解已足够，未优化空间利用的均衡性**。四个样例均 100% 贴墙，满足
  题目要求，但物体倾向于集中在排序靠前的长墙上（如 example3 全部沿左墙），
  中部留有较大空地。若要求布局更均衡，可在目标函数中加入墙面使用的分散度项。
- **离地架按不可重叠处理**。`reference/image01.png` 标注离地架高 120mm，
  物理上其下方可容纳其他物品，但本题为二维问题，当前实现禁止任何重叠。
  若允许，可行率会显著提高。
- **冰箱开门区进深是假设值**（600mm，题目未给定）。可通过
  `--fridge-clearance` 调整，影响见 1.6 的实测数据。
- **未建模通行路径的连通性**。当前只保证门洞不被遮挡，不检查门到各物体之间
  是否存在可通行路径。在更窄的房间里有可能出现物体围成死角的布局。
- **接触点枚举可能留下小缝隙**。先放置的物体会固定其开门区边界，后续物体
  自另一端向内排布时可能无法恰好对齐，例如 example4 中 overShelf-1 顶边与
  冰箱开门区之间有 30mm 空隙。这只是未利用空间，不违反任何约束。
